## 2. Slice selected for the team (exact filters)

The dataset has tens of millions of rows, so the team uses a small, reproducible slice.

| Filter | Value |
|---|---|
| Created Date, start (inclusive) | 2026-07-01 00:00:00 |
| Created Date, end (exclusive) | 2026-08-01 00:00:00 |
| Borough | BROOKLYN |
| Row limit requested | 500000 (must be higher than the real row count; see section 4) |

Equivalent SoQL filter:

```
created_date >= '2026-07-01T00:00:00' AND created_date < '2026-08-01T00:00:00' AND borough = 'BROOKLYN'
```

Rationale: one month and one borough keep the file small enough for an offline laptop analysis while still containing several agencies and complaint types to rank and compare.

## 5. Known limitations

- Requests created late in the window may still be open at export time; their closed date is
  therefore blank, and they must not be used for closure-time statistics.
- Findings describe only this slice (one borough, one month) and must not be generalised to
  all of New York City or to other time periods.
- The portal's column labels changed in December 2025 (for example "Complaint Type" is now
  labelled "Problem"), but backend/API field names did not change. The parser should accept both.

## 6. Reproduction steps

1. `pip install -r requirements.txt` and `python scripts/check_environment.py`
2. `python scripts/build_export_url.py`, then download the CSV with those filters
   (or follow `PORTAL_FILTER_STEPS.md`).
3. Save the file to the path in `config/dataset_config.json`.
4. `python scripts/verify_dataset.py` and compare the SHA-256 with section 4.
